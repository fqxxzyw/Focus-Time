# 专注时光 · Focus Time

番茄钟，专注于眼前，遇见更好的自己。

一个中文、纯本地的番茄钟与生活记录工具。

- 在线版：[Sites 打开专注时光](https://focus-time.fqxxzyw.chatgpt.site)
- Windows 安装版、免安装版与网页静态包：[GitHub Releases](https://github.com/fqxxzyw/Focus-Time/releases)
- 源码仓库：[fqxxzyw/Focus-Time](https://github.com/fqxxzyw/Focus-Time)

React 19 + TypeScript + Vite；IndexedDB 保存业务数据，localStorage 保存轻量设置副本。无账号、后端、云同步、付费 API、追踪脚本及外部图片请求。内置背景为原创 CSS 渐变。MIT 开源。

## 快速开始

需要 Node.js 22+ 与 npm。解压后，在 `focus-time` 目录运行：

```bash
npm ci
npm run dev
```

打开终端给出的 `http://127.0.0.1:5173`。请使用 HTTP 服务，不要直接双击 `index.html`。首次使用是空数据，默认提供学习、工作、个人生活三个空待办集。设置页可主动加载演示数据，或导入仓库中的 `demo-data.json`。

```bash
npm test                 # 核心业务与 IndexedDB 测试
npm run typecheck        # TypeScript 检查
npm run build            # 生产构建 → dist/
npx vite preview --host 127.0.0.1
npx playwright install chromium
npm run test:e2e         # 浏览器验收；使用模拟时间，不实际等待 5 分钟
npm run format           # 统一源码格式
npm run demo:export      # 重新生成可手动导入的演示备份
```

## 功能

- **专注**：番茄钟、正计时、倒计时；任务关联、临时名称、暂停继续、结束与提醒；默认 25/5/15 分钟，每四次自然完成的专注安排长休息；自动下一阶段默认关闭。
- **任务**：每日任务、分类与多个待办集、上下移动排序、日期/分类/待办集/状态筛选、编辑/完成/确认删除。
- **周期**：每日、每周指定星期、每月指定日期，开始与可选结束日期；模板与实例分开保存；打开或回到应用时补齐截至今天的实例；不存在的月日期跳过。去重标记保留，手动删除的实例不会再次生成。编辑模板不改已生成实例；删除模板可选择保留实例或同时删除未完成实例。
- **统计**：今日/月/年/全部/自定义；趋势、年度热力图、任务占比与其他明细、分类与单任务视图、本月打断原因和 24 小时时段分布。任务删除后依旧通过历史快照显示为“已删除”。
- **生活**：上床/起床打卡、补录编辑、配对估算卧床、连续夜间轴分布。未来事件支持本地日期时间、置顶、编辑、删除和到期状态。
- **成就**：八枚徽章、真实数据自动计算进度、解锁时间与一次性提醒。历史解锁保留。
- **资料/设置**：本地头像、昵称、简介、每日目标；明暗/系统主题、滚动/翻页数字、随机/自选渐变/纯色/本地图片背景、音量、一周起始日。
- **数据保护**：版本化 JSON 导入导出，格式/关系校验和摘要确认后整体替换；清空确认；读取/保存/导入失败提示；读取损坏时支持抢救导出原始数据和导入有效备份。

## 计时与统计口径

1. 一次会话以 UUID 唯一标识。有效时间 = 多个运行区间的秒数之和；运行期间使用当前时间戳减去开始锚点。暂停不累计。完成操作有状态保护，不会再创建一个相同会话。保存采用一个 IndexedDB 事务写入完整快照，以免任务、事件和会话只写入一部分。
2. **累计未满 300 秒**的专注保留为“未达标”，所有统计与成就均不计入其时长和次数。暂停后继续累计，可跨越门槛。满 300 秒后自然结束或主动结束都计为一次有效专注。
3. **完成番茄数**仅包括有效、自然归零的番茄专注；提前结束、正计时、普通倒计时均不增加完成番茄数。休息永远不计入专注统计。番茄循环的阶段安排依据自然完成的番茄专注次数；设置少于五分钟时自然完成仍推进循环，但不入账。
4. 保存真实的毫秒区间，计算保留原始秒数（可有小数），只在显示时格式化。跨午夜、月份、年份的区间按用户当前当地日期切分；跨小时分配到对应小时。每次专注是否有效先根据整次会话判断，然后将它的全部有效区间分配到各日。
5. 有效次数和完成番茄数归入**会话结束日期**，不是开始日期；自然倒计时后台超时的结束日期是实际目标归零时间。自定义范围包含起止日期整天。
6. 范围内平均时长 = 范围内有效区间总秒数 ÷ 范围内结束的有效会话次数；为零次时显示零。由于跨日会话的时长与次数归属不同，某日可能有时长但零次，平均值不会被当作“完整会话均值”。
7. 已完成任务采用独立完成台账：每个任务实例首次标记完成时记录一次，取消完成后再次勾选不重复增加历史完成数；删除任务不减少台账。单任务统计仅包含该任务的台账。徽章的完成任务条件也使用这个台账。
8. 暂停/提前结束先保存一条默认“未填写”的打断事件，选择原因后更新同一 ID。跳过、关闭或刷新均不会重复写入；多次操作可以产生多个不同事件。本月打断图按**事件时间/事件次数**，包含未达标会话的打断，不等于专注次数。
9. 正计时刷新/重新打开会累计离开期间的运行时间，然后暂停并展示恢复结果，用户确认后继续或结束；已经暂停的状态保持暂停。有限目标的计时最多累计目标秒数，并恢复为完成。恢复不会回填多个自动番茄阶段，也不会把离开后的余时算入另一个阶段。
10. 活跃连续天数从今天（已有专注）或昨天（今天尚未专注）向前计算；历史最长连续天数用于三日/七日徽章，已解锁不撤销。跨日区间让有有效秒数的日期均成为专注日。
11. 上床不代表入睡。打卡按时间排序，将上床与其后首个起床配对；连续上床时前一条标为不完整，孤立起床也不完整。只展示有两端的卧床估算，不制造缺失数据。夜间轴将 00:00–17:59 映射到 24:00–41:59，使 23:50 与 00:10 接近；常见范围展示 18:00–次日12:00，超出窗口的点仍保留。

## GitHub Pages 发布

仓库推荐名：`focus-time`。简介可用：

> 专注时光：本地优先的中文番茄钟，集任务、专注统计、生活打卡与成就于一体。React + TypeScript + Vite，无需后端。

将**这个目录的内容**作为仓库根目录推送到 `main`，然后在 GitHub 仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。已提供 `.github/workflows/pages.yml`，在 Actions 中手动运行 Deploy GitHub Pages 后，会安装锁定依赖、执行测试与类型检查、构建并部署。部署地址一般为 `https://你的用户名.github.io/仓库名/`。已同步本仓库；Sites 网页已发布。GitHub Pages 是可选的额外托管方式。

默认 Vite `base` 为 `./`，静态资源支持仓库子路径；工作流使用仓库名设置 `BASE_PATH`。如果是 `用户名.github.io` 根站或自定义域名，请把工作流的 `BASE_PATH` 改为 `/`。Windows PowerShell 手动指定子路径：

```powershell
$env:BASE_PATH='/focus-time/'
npm run build
```

应用采用状态式页面导航，无深层路由，因此无需 404 回退。首次发布后检查字体、图片、脚本、主题、计时和备份能正常加载。更换域名会更换浏览器存储来源，需要手动备份迁移。相同 GitHub Pages 域名上的不同仓库共享同一个浏览器 origin，本应用使用独立数据库名称，但多份本应用的部署会共用数据。

推荐首发标签 `v1.0.0`，Release 标题 **专注时光 v1.0.0 — 把时间留给重要的事**。附件可上传源码 zip 与 `dist` 静态部署包。

## 备份与隐私

设置 → 导出 JSON 备份，包含版本、资料、设置、图片、待办集、任务、模板、生成标记、会话区间与快照、打断事件、未来事件、生活打卡、完成台账及徽章。导入只接受本项目版本 1；校验字段类型、日期、重复 ID、有效区间、活动会话数、部分实体引用及背景图片格式，然后展示摘要供确认，采用**整体替换**，不合并。

备份包含个人记录与图片，请妥善保管。上传图片只保存为本地数据，单张不超过 4 MB。导入文件限制 30 MB。轻量设置有 localStorage 副本，IndexedDB 中另有完整备份；不同步的缓存不会覆盖主数据。正常浏览器支持 Web Locks 时只允许一个标签页操作，防止多个页面互相覆盖。

## 已知限制

- 纯前端本地保存，不跨设备同步；浏览器清理、隐私模式、磁盘配额及卸载可能导致数据丢失。需定期备份。
- 计时依赖设备系统时钟；手动调整时钟可能影响正在运行的会话。记录的日期按当前查看设备时区解释，跨时区迁移可能改变日期归属。夏令时使用本地日期边界切分。
- 系统可能禁止后台声音，页面关闭时无法发声或通知；重新打开仍按时间戳恢复。没有 Service Worker，不提供首次离线访问与系统通知。
- Web Locks 不可用的旧浏览器请只开一个标签页。支持的现代浏览器优先；本次真实浏览器验收为 Chromium，不代表已测试所有浏览器或真实手机硬件。
- 小时分布在夏令时回拨的重复小时会合并至同一小时标签；数据库采用完整快照事务写入，海量记录/图片下有性能上限，暂无分页、压缩、导入合并或多版本迁移。
- 睡眠配对为时间顺序估算，不识别多段午睡/跨日手工配对；历史打卡最多在配对列表展开 60 行，完整原始打卡仍可在“编辑所有打卡”与导出中查看。
- 图表使用 Recharts 2.x，保留当前锁定依赖便于复现；未来升级到新主版本需单独验证。

验证证据与执行情况见 [docs/VERIFICATION.md](docs/VERIFICATION.md)。

## Windows 桌面版

从 Release 下载 Setup 安装版（可选择目录）或 Portable 免安装版。桌面版自带运行环境，不需要安装 Node.js，使用相同的七个功能页面。资料、任务和备份均保存在本机，网页与桌面数据不自动互通，可通过 JSON 导出/导入迁移。Windows 的应用数据默认位于 `%APPDATA%/专注时光`；升级保留数据，卸载默认不删除数据。

桌面窗口使用 `focus://app` 固定安全 origin，使 IndexedDB 能在安装升级后继续恢复。不启用 Node.js 渲染器权限；启用上下文隔离与 sandbox，只读取打包的前端资源。

```bash
npm ci
npm run desktop          # 本地启动开发桌面窗口
npm run package:win      # Windows x64 安装版 + 免安装版 → release/
npm run package:win:dir  # 仅生成 unpacked 桌面目录
```

在 Windows 上执行打包最可靠；已配置 Windows GitHub Actions 自动构建、启动打包窗口验收、压缩网页并上传 Release。修改代码后发布新版本时先递增 package.json 的 version，避免重复使用版本号。安装包未进行商业代码签名，系统可能出现未知发布者提示。

网页包含全量功能；EXE 只是本地运行载体，不额外添加账号、同步或付费服务。
